# 用客户端地图数据生成可走格子，提前规划绕障路线

- 编号：20261116-walk-grid-pathing
- 状态：离线自检通过（2026-11-16），待游戏验收 G2–G4
- 来源：新需求（2026-11-16，用户：“最大的问题还是如何识别障碍点，自动避开或者绕过”）。依据可行性验证 `20261115-navmesh-feasibility.md`（F1–F4 通过，F5 初步通过）
- 发布版本：

## 1. 问题记录与分析

- 现象：
  - 助手只能“撞上再绕”：连续 5 次前进不足 0.15 码判为受阻，然后按固定几何绕行（侧移 6 或 11 码、前进 12 或 16 码），最多试两次，之后停下。
  - 遇到比侧移距离长的障碍（房子、围墙、山丘）就过不去。
  - 撞过的地方不记，下次在同一处再撞。
- 典型证据：2026-11-15 赤脊山跑尸卡住 4 个多小时（`20261115-ghost-graveyard-exit.md`）。
  - 灵魂出生点 (23.20, 45.41) 紧贴一座房子的西墙。
  - 直线去尸体正好顶进房子墙角（用户 2026-11-16 在该点确认“跑到了一个房子的墙角”）。
- 根因：助手没有任何地形与障碍信息。插件拿不到碰撞数据，读游戏内存已被用户否决。
- 可行性结论（`20261115-navmesh-feasibility.md` 第 5 节）：
  - 本机客户端 `wowf` 1.60.1 的地形、建筑、物件碰撞文件都能离线只读取出，不需要密钥。
  - 生成赤脊山 1 码格子图约 23 秒。
  - 道路格子受阻 3.1%（坡度中位数 9.5°）。
  - 墓地房子在格子图上与用户描述的墙角位置吻合。
  - 寻路算出“先向南绕过房子再往东北”，纯 Python 版 0.17 秒。
  - 格子文件压缩后约 0.65 MB 一张地图。

### 复现用例

- 离线测试 `tests/test_walk_grid.py`（合成数据，不含游戏数据）：
  - **R1 房子墙角**：合成一张地图，起点贴着一个 L 形墙角，目标在墙后 40 码。
    - 现状：`MapNavigator` 撞墙后两次 `_LocalDetour` 都受阻，以“绕行各可用方向均受阻”停下。这条断言作为现状记录。
    - 开关打开且有格子图时：受阻后改走格子路线，各路点不穿墙，最终到达目标。
  - **R2 灵魂跑尸**：灵魂出生点在墙角、尸体在墙后，且没有录制轨迹和接入路线。
    - 现状：直行 → 尸体旁探点 → 停下等待。
    - 开关打开时：开局就按格子路线出发，日志“已按地图格子规划跑尸路线”。
- 修复前运行结果：实现前先写这两个用例并确认失败（模块不存在、日志中没有规划记录），结果贴回第 5 节。

## 2. 设计

### 目标与非目标

- 目标：
  1. **生成**：命令行工具从本机客户端文件生成指定地图的“可走/受阻”格子图，存在 `.local/walkgrid/`（已在 `.gitignore`），不提交、不发布。
  2. **跑尸**：灵魂同地图跑尸时，如果没有录制轨迹和起点接入路线，开局就按格子图算出整条路线再走。
  3. **绕障**：任何导航（练级、巡逻、跑尸、补给）撞墙后，先在格子图上算绕行路线；算不出来再退回现有的固定绕行。
  4. **本次运行的临时障碍**：格子图上算可走、实际撞上的地方，在本次运行中标记为受阻，重算时避开。只存内存，不写文件。
- 非目标（第一版不做）：
  - 多层地形：桥面、建筑内部、洞穴。这些地方继续用录制路线和道路表。
  - 怪物等动态障碍；游泳路线优化。
  - 用格子图替换跨地图的道路表。
  - 自动标定：每张地图第一次要用户在游戏里 `/dump` 一个点，以后可改成插件自动上报，那需要改协议，另立设计。
  - 发布包里带格子图：格子图来自游戏数据，只在用户本机生成。
- 保持不变的行为：
  - 开关关闭时，与现在完全一致。
  - 录制跑尸轨迹、手动起点接入路线的优先级仍高于格子路线。
  - 插件、像素协议不改，不改 `DEV_VERSION`，不用重装插件。
  - 撞墙检测（5 次脉冲）不变，只换“撞上之后怎么绕”。

### 方案与数据流

- **插件端、像素协议**：不改。
- **生成**（离线，用户手动运行一次）：
  1. 输入：游戏目录（读 `.build.info` 选 `wowf` 产品），地图编号（如 1433），标定点（世界坐标 + 地图百分比，来自 `/dump UnitPosition("player")` 和 `C_Map.GetPlayerMapPosition`），以及地图尺寸（码，插件已上报，状态快照中可见）。
  2. 处理：只读 CASC → 大陆 WDT（东部王国 775971，卡利姆多 782779）→ 覆盖地图范围的 ADT 地块 → 地形高度（1 码格）+ 物件碰撞三角形（M2 碰撞数据、WMO 碰撞面）→ 受阻判定。
     - 受阻条件：坡度大于 55°；或地面以上 0.6–2.2 码有碰撞面；或地形空洞。
     - 再向外扩 1 格作为角色半径。
  3. 输出 `.local/walkgrid/<地图编号>.wgrid`：一行 JSON 头 + zlib 压缩的 `uint8` 代价格。
     - JSON 头含版本、地图编号、行列数、每格码数、世界边界、客户端构建号、生成参数、生成时间。
     - 代价格：0 为受阻，1–254 为通行代价，坡越陡代价越高。
  4. 同时输出一张预览图 `.local/walkgrid/<地图编号>.png`，供用户核对。
  5. 标定点存入 `.local/walkgrid/calibration.json`，重新生成时复用。
- **运行时**：
  - 格子以“地图百分比”为坐标，所以运行时不需要世界坐标。
  - 只在受阻、开始跑尸等事件时规划，不每帧计算。
  - 规划步骤：
    1. 起点、终点各自吸附到 6 码内最近的可走格子；
    2. A* 搜索，扩展上限约 40 万格（约 1 秒），超限算失败；
    3. 用视线检查把格子路径压成间隔不超过 25 码的路点。
  - **跑尸**（`DevWindow` 同地图跑尸路由）：
    - 顺序：录制轨迹 → 起点接入路线 → **格子路线（新增）** → 营地道路 → 直线加尸体旁探点。
    - 格子路线做成与录制轨迹相同的 `WalkingTrip`（`camp_road` 为格子路点），走完由原逻辑接管复活。
  - **绕障**（`MapNavigator`）：
    - 连续 5 次受阻且有格子图时，先把撞墙方向前方 1–3 码标为本次运行的临时障碍。
    - 再从当前位置向目标点规划，生成 `_GridDetour`：沿用 `_LocalDetour` 的路点跟随与超时机制，只是路点来自格子图。
    - 规划失败（无路、超限、目标不在格子图范围内）时，回到现有 `_LocalDetour`。
    - “本次最多绕两次”的上限不变。
  - **灵魂出不了墓地**（`GhostOrigin`）：逻辑保留，作为格子路线也失败时的最后提示。

### 客户端界面

- 开发版专有控件（`DevWindow._configure_unfinished_controls`），放在无人托管相关控件旁：
  - 复选框“地图格子寻路（实验）”，默认不勾。
  - 提示文字：“按 .local/walkgrid 中的地图格子规划跑尸路线和撞墙后的绕行。没有对应地图的格子文件时不起作用。”
  - 随时可改，下一次规划生效；保存为 `automation/walkGrid`。
- 日志：
  - 开始监控时（开关打开）：“地图格子：已找到 赤脊山（1433）”，或“地图格子：.local/walkgrid 中没有格子文件”。
  - 跑尸：“已按地图格子规划跑尸路线，共 N 个路点，约 M 码。”
  - 绕障：“直行受阻，按地图格子绕行前往「X」（N 个路点）。”
  - 失败：“地图格子未找到绕行路线（原因），改用局部绕行。”
- 生成工具第一版只有命令行，由用户在终端运行（可用 `! 命令`），输出统计和预览图路径。

### 开关与回退

- 独立开关 `automation/walkGrid`，默认关闭，游戏验收通过后再讨论默认开启。
- 关闭开关或没有格子文件：完全回到现有行为（固定绕行、尸体旁探点）。
- 格子文件损坏、版本不符：日志提示一次，按“没有格子文件”处理。

### 风险

- **游戏数据使用**：只读本机客户端文件，不读进程内存；格子文件只在本机，不提交、不发布。是否符合用户协议由用户判断，用户已决定使用。
- **障碍遗漏**：
  - WMO 内部摆放的小物件（家具、栅栏等）第一版不计；
  - 物件旋转约定只用赤脊山房子和道路吻合度间接验证过。
  - 应对：撞上后记临时障碍再重算，仍失败就退回固定绕行。
- **2.5D 局限**：桥面、室内、洞穴没有表示，格子路线可能绕远或走水下。这些地方的录制路线优先级更高。
- **坡度阈值**：55° 是经验值，偏严会绕远，偏松会卡坡；放在生成参数里，验收时调整。
- **性能**：A* 只在事件发生时运行，有扩展上限（约 1 秒）。格子图第一次用时解压（约 3 MB 内存一张地图），不进每帧路径。
- **测试打桩**：保留 `_LocalDetour`、`MapNavigator.observe` 等现有名字；`decode_*` 打桩方式不变。
- **标定**：每张地图需要一次 `/dump`。标定点填错会让整张图偏移，生成工具会用道路表做吻合度自检：道路受阻比例大于 10% 时警告。

## 4. 实现记录

- 先写 `tests/test_walk_grid.py`（核心、R1、R2）并确认失败，再按模块顺序实现。
- `core/walk_grid.py`：
  - 纯标准库：`WalkGrid`（`from_blocked`、`from_bytes`、`to_bytes`、`snap`、`find_path`、`block_ahead`、`clear_temporary`），外围补一圈受阻格。
  - 路点合并：贪心视线，每段不超过 20 码，并做 5 码转角检查。为控制耗时，每个锚点只看 20 码窗口内的格子，外加终点。
- `automation/grid_route.py`：`GridRoutes` 按地图懒加载；地图尺寸与格子文件相差超过 1% 时拒绝规划；`last_plan` 供状态快照使用。
- `automation/navigation.py`：
  - 新增 `_GridDetour` 和 `MapNavigator.grid`、`_grid_detour`、`_start_detour`。
  - 固定局部绕行的文字、次数上限与原来一致。新目标、换图、到达、离开 24 码范围时，格子重算次数清零。
- `app/dev_window.py`：
  - “地图路线”菜单新增“地图格子寻路（实验）”（可勾选，保存为 `automation/walkGrid`）。
  - `_corpse_route` 在同一地图时先试 `_grid_corpse_road`。格子跑尸路线受阻时放弃并回到常规跑尸。每帧把 `navigator.grid` 设为当前开关状态对应的对象。
  - 状态快照新增 `walk_grid`。
- `automation/unattended_phases.py`：复活或生死状态变化时清空格子跑尸状态。
- 生成工具：
  - `tools/walkgrid/`（`casc.py`、`terrain.py`、`rasterize.py`）与 `tools/build_walk_grid.py`。
  - 标定点存在 `.local/walkgrid/calibration.json`；两点以上用最小二乘求尺寸和偏移。
  - 生成后用设置中的实走轨迹自检。
  - 外扩改为 8 邻域，比可行性验证时的 4 邻域更保守。
- `requirements-dev.txt` 加 `numpy==2.5.5`，只给生成工具用；已用 uv 装进 `.venv`。
- 偏离设计：
  - 墙边代价、坡度代价、外扩都在生成时写进代价格，运行时只读；
  - 格子跑尸路线受阻后不在窗口层再重算（导航器内部已重算三次），直接回到常规跑尸；
  - 开关已打开时，启动助手不再写日志（只在勾选时写）；
  - 生成工具用设置中的实走轨迹自检，没有用人工道路表。实走轨迹更能说明问题，人工道路表的结果见可行性文档；
  - 游戏目录第一次运行时用 `--game-dir` 给出，之后记在 `calibration.json`，不写死在代码里。
- 第二轮（2026-11-17，离线仿真发现问题后修正）：
  - **仿真**：真实 `WalkingTrip`（手动路点）+ `MapNavigator` + 格子联合运行，移动撞到原始受阻格就不动。在本机赤脊山格子上，从出生点出发卡住。原因有两个：
    1. 出生点本身在墙线上，前两个路点都在 5 码到点半径内，被连续跳过；角色从墙线上直接斜着切向第三点，擦到墙角。
    2. 撞墙后标记的 3 码宽临时障碍，把南侧唯一的窄口整个堵死。
  - **修正**：
    - 连线检查改为角色左右各留 0.5 码，查三条线；
    - 转角检查沿已保留的折线往回量满 5 码，可跨多段；
    - 规划因临时障碍失败时，忽略临时障碍再试一次；
    - 临时障碍 10 分钟后失效，状态快照显示数量（`walk_grid.temporary_cells`）。
  - **格子跑尸路线改用“手动路点”方式**（`catalog_goal`，与录制轨迹相同）：从首点依次走，不按直线距离接入；也不进入赤脊山湖边陆路的特殊处理（`redridge_camp_requires_road`）。
  - 复活（活着）时清空格子跑尸状态，不只在无人托管时。
  - “地图路线”菜单打开提示显示（`setToolTipsVisible`）。
- **建筑旋转约定核对**：
  - 赤脊山 62 个建筑的模型包围盒（MOHD）8 个角点，按本工具的换算求出的外接框，与 MODF 记录的摆放外接框最大相差 0.002 码；偏航取反时最大相差 139 码。
  - 小物件（M2）用同一换算函数。

## 实现细则（确认后补充，不改变行为范围）

- **真实轨迹对照**：用户录制的赤脊山循环路线（设置 `automation/patrolRoute`，31 个点，706 格）原始受阻 0.1%，外扩后 0.8%，平移 ±4 格内没有更优的偏移。比人工道路表（3.1%）更能说明格子图准确。
- **起点吸附**：出生点和墙在同一个 1 码格内时，取南、北哪一侧只差 0.2 码。规则改为：
  - 用格子内的精确位置；
  - 候选格从当前位置连直线，不能穿过原始受阻格（角色所在 0.75 码内的格除外）；
  - 导航器绕行时，优先选靠近刚走过轨迹（`_trail`）的一侧。
- **`_GridDetour` 与 `_LocalDetour` 的区别**：
  - 范围上限按路线实际长度计算，不再是 18/24 码；
  - 脉冲上限随路线长度增加；
  - 到点半径 2.5 码；
  - 走完最后一个路点就结束绕行，交回直行。最后一个路点与目标之间已确认无遮挡，所以不要求比出发时更近。
  - 绕行中受阻：记临时障碍后重新规划，最多 3 次；之后改用原来的局部绕行，次数上限不变。
- **格子跑尸路线受阻**：导航器内部已重算 3 次仍停下时，本次灵魂放弃格子路线（日志说明），回到营地道路 → 直线与尸体旁探点 → `GhostOrigin` 提示。不再进入“保留原路点等待”。
- **路线起点**：格子跑尸路线的第一个路点是灵魂当前位置，避免 `WalkingTrip` 按直线距离接到墙另一侧的路点。
- **转角余量**：
  - 生成格子图时，受阻格 3 码内加通行代价，让路线离墙；
  - 合并路点时，要求从上一路点前 5 码（道路到点半径）切向下一路点，也不穿过受阻格或外扩格。
- **规划前先松开前进键**。
- 本次运行的临时障碍只存在内存里。
