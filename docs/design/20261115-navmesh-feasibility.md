# 寻路网格可行性验证（基于客户端地图数据文件）

- 编号：20261115-navmesh-feasibility
- 状态：验证中。2026-11-15 暂缓；2026-11-16 用户同意启动，F1 已通过，F2/F3 待用户确认。
- 来源：新需求（2026-11-15，讨论循环打怪绕障时用户决定尝试；读取游戏内存的方案已被用户否决，不做）
- 发布版本：不发布（验证性工作）

## 1. 背景与分析

- 插件拿不到地形、碰撞与寻路数据，助手只能直线走、撞上再绕（见 `20261115-recorded-patrol.md`）。
- 客户端目录 `D:\Program Files (x86)\World of Warcraft1.14\Data` 为 CASC 存档（`config`、`data`、`indices`，约 54 GB），含产品 `wow_classic_era` 与 `wowf`（无限版，经 Arctium 启动器与 HermesProxy 连私服）。
- 私服常用 TrinityCore 等开源工具从客户端数据离线提取地形（ADT）、建筑（WMO）、物件（M2）碰撞，并用 Recast/Detour 生成寻路网格（navmesh）。若对本客户端可用，助手可在网格上规划绕开障碍的路线，不依赖视觉识别。
- **只读取本机客户端数据文件**，不读取游戏进程内存；提取结果只留在本机（`.local` 或仓库外目录，不提交、不发布）。提取游戏数据是否符合用户协议由用户判断，用户已决定尝试。

## 2. 要回答的问题

## 3. 验证方案（分步，每步完成后报告结果再继续）

1. **工具选型与准备（需用户同意下载）**：候选为 CascLib（读 CASC）与 TrinityCore 的地图/vmap/mmap 提取生成工具，或其他支持现代 CASC 的开源读取器；寻路库为 Recast/Detour。下载与编译放在仓库外的工作目录，记录来源、版本与许可证。
2. **F1**：只读打开 CASC，列出 `wowf` 产品中赤脊山所在大陆（东部王国）的地图文件与 `Map`、`UiMapAssignment` 等数据库文件；记录是否需要密钥。
3. **F2、F3**：提取东部王国中覆盖赤脊山的地图块，生成网格；记录耗时、大小与报错。
4. **F4**：用 `UiMapAssignment` 等数据把地图百分比坐标换算到世界坐标；用游戏里几个已知坐标点（用户站在固定地标处报告插件读数）核对误差。
5. **F5、F6**：在网格上计算 `walking_route.py` 中已核对道路的起点到终点路线，比较两者偏差；在赤脊山桥与建筑附近检查分层。
6. **结论**：写明可行、部分可行或不可行，以及全面接入时的工作量与风险，交用户决定是否立项实现。

### 模块归属

验证阶段只新增仓库外的实验脚本与本文记录，不改助手代码；如需在仓库内保留可复用的小工具（如坐标换算），放在 `tools/` 并附测试，经用户同意后再加。

### 风险

- 私服产品 `wowf` 可能使用定制数据或额外加密，现成工具无法读取。
- 工具链依赖 C++ 编译环境（如 Visual Studio Build Tools），可能需要额外安装。
- 提取与生成需要较多磁盘空间与时间（单张大陆可能数 GB、数十分钟）。

## 5. 验证记录

### F1 读取存档（2026-11-16，通过）

- 用户 2026-11-16 同意先做 F1。没有下载 CascLib，也没有安装编译环境：本机无 .NET，也无 C++ 编译器，所以改用 Python 写了一个约 200 行的只读 CASC 读取器。
  - 读取器只用标准库，放在会话临时目录 `scratchpad/navmesh/casc.py`，不进仓库。
  - 流程：`.build.info` → 构建配置 → 本地索引 `*.idx` → `data.###` → BLTE 解压 → encoding → root（MFST v2）。
  - 只读文件，不碰游戏进程。
- 产品与版本：`wowf` 1.60.1.70938（构建名 `WOW-70938patch1.60.1_Retail`，`client-version = 3.12.0`）。`.build.info` 中 KeyRing 与 Armadillo 均为空，说明本地存档没有整体加密。
- 打开耗时 3.4 秒：
  - 本地索引 1,231,328 项，encoding 2,209,350 项；
  - root 有 1,251,159 个文件编号，但只有 145,009 个带文件名哈希，所以大部分文件要按文件编号（FileDataID）取，不能按路径名取。
- 地图文件（东部王国 Azeroth，WDT 文件编号 775971）：
  - WDT 的 `MAID` 列出 736 个地块。全部地块的地形文件（root）和物件文件（obj0）共 1,472 个，**全部读出，0 加密，0 缺失**。
  - 赤脊山附近 5×5 个地块（`azeroth_34..38_47..51`）的 root、obj0、tex0 共 75 个文件全部读出。
  - 赤脊山 3×3 个地块（35–37 × 48–50）引用的物件全部可读：
    - 树、石头等小物件（M2）3,233 处、351 种；
    - 建筑与墓地围墙（WMO）45 处、31 种，这些建筑包含 98 个分组文件。
  - 所有引用都是文件编号，不需要外部文件名表（listfile）。
- 数据库：
  - `UiMap`（1957206）、`UiMapAssignment`（1957210）可读，格式为 WDC5。F4 需要它们做坐标换算。
  - `Map`（1349477）和 `AreaTable`（1353545）各有 3/5 的数据块加密（BLTE 的 `E` 块），没有密钥。按惯例可以把加密块当空块跳过，读其余部分；而且东部王国的地图编号 0 已知，不影响后续步骤。
- 结论：**F1 通过**。私服产品 `wowf` 的地形、建筑和物件碰撞源文件都能离线取出，不需要密钥。

### F2/F3/F4 赤脊山格子图（2026-11-16，方案 A：Python + numpy，初步通过）

- 用户选方案 A。numpy 装在会话临时目录的独立虚拟环境里，没装进项目的 `.venv`。实验脚本 `grid.py`、`world.py`、`astar.py` 也在会话临时目录。
- **做法**（2.5D 近似）：
  - 地形：用 MCVT 的 145 个高度点，按每格 4 个三角形插值，得到 1 码格的地面高度。检查过地形块接缝，误差为 0。
  - 物件：取碰撞三角形——小物件（M2）用 0xD8 起的碰撞数据，建筑与墙（WMO）用 MOPY 标出碰撞面。按 TrinityCore mmaps 的约定摆到世界坐标，按 0.35 码间距采样。
  - 受阻条件：碰撞面落在地面以上 0.6–2.2 码的格子算受阻；坡度大于 55° 也算受阻；再向外扩 1 格作为角色半径。
  - 用时：赤脊山 2170×1447 格，约 2,968 个小物件、47 个建筑、20.7 万个三角形，生成用时约 23 秒。
- **F4 坐标换算**：
  - 凭记忆填的经典版边界差了 110–230 码，道路处坡度中位数 25°，与随机点差不多。
  - 改用用户在游戏里测的一个点标定：`UnitPosition` 为 (-9089.30, -2407.80)，地图坐标为 (33.47%, 35.52%)，尺寸沿用桌面端的 2170.8×1447.9 码。
  - 得到边界：左 -1681.2、右 -3852.0、上 -8575.0、下 -10022.9。
  - 第二个点核对（2026-11-16）：`UnitPosition` 为 (-9233.20, -2190.40)，地图坐标为 (23.45%, 45.46%)。两点反推出的尺寸为 2170.5×1447.7 码，与 2170.8×1447.9 码相差不到 0.02%。**F4 通过**：同一张地图内，用一个固定偏移加桌面端已有的尺寸就能换算。
  - 第二个点就是用户说的卡点“房子的墙角”，在出生点以东约 5 码。格子图上，这个点的北侧 1 码有东西向的墙，东侧 5 码有南北向的墙，正好是一个墙角，与用户描述一致。
- **F5 道路对照**：
  - `walking_route.py` 中赤脊山各条道路共 2,087 格：坡度中位数 9.5°，受阻 3.1%；算上角色半径外扩 1 格后受阻 6.7%。
  - 全区受阻 29.1%，主要是山地陡坡。
  - 道路上受阻的格子还没逐个查，估计在桥上（2.5D 模型没有桥面）或贴着墙。
- **墓地出口**：
  - 灵魂出生点 (23.20, 45.41) 紧贴一座房子（建筑轮廓约 50×35 码）的西墙；用户确认卡住的位置是这座房子的墙角。
  - 寻路结果：先向南出围墙缺口，再往东、往北绕过石丘到尸体 (30.48, 28.24)。全程约 458 码，直线距离 295 码。
  - 这与 20261115-ghost-graveyard-exit 的现象吻合：直线朝东北走，正好顶着墙。
  - 图片：会话临时目录 `navmesh/crop_path.png`、`crop_spawn.png`。
- **局限（F6）**：
  - 只有一层地面，桥面、建筑内部、洞穴没有表示。
  - 水域按水底地形算。
  - 物件的旋转约定只用围墙形状、道路吻合度间接验证过。
