# 沿轨迹转向改进

- 编号：20261115-path-steering
- 状态：第 1 步“转向指标采集”离线自检通过（2026-11-15）；基线数据 T5 待用户跑圈采集
- 来源：用户反馈（2026-11-15，录制循环路线 Q1 验收期间）：“方向的转向判断可以用，但不是最优解”
- 发布版本：（发布后填写）

## 1. 问题记录与分析

### 现状（`automation/navigation.py` `MapNavigator.observe`）

- 每帧比较角色朝向与“指向当前路点”的方向；偏差超过约 0.16–0.20 弧度（9–11°）时点按 A/D 一次，时长与偏差成正比（转弯中 180 ms/弧度、上限 100 ms；原地 260 ms/弧度、上限 120 ms），每帧只点一次。
- 偏差超过 `_STEERING_LIMIT = 0.65` 弧度（约 37°）时松开前进键，原地转向后再走。
- 转速与按键到朝向变化的延迟没有实测，为写死的估计。

### 根因与表现

| # | 根因 | 表现 |
|---|---|---|
| S1 | 只对准下一个路点，不看路线形状 | 左右来回修正（锯齿）；从当前位置直奔路点，切掉录制轨迹的弯，可能撞上录制时绕开的障碍 |
| S2 | 大角度时停下原地转 | 拐点处急停、再起步 |
| S3 | 转速与延迟为估计值 | 按键时长与实际转角不匹配，修过头或修不够；效果随机器帧率变化 |
| S4 | 没有量化指标 | 改进好坏只能凭感觉判断 |

## 2. 设计

### 方案（按步骤推进，每步离线自检后游戏实测）

1. **转向指标采集（S4，先做）**：录制路线回放时，按段（上一停留点 → 当前停留点）统计：用时、偏离录制轨迹的最大与平均距离（码）、原地转向次数、转向点按次数、受阻次数；到达停留点时写一行日志“转向统计 · 第 k 段：…”，并累计整圈汇总。作为改进前的基线与改进后的对比依据。只读统计，不改变移动行为。
2. **前视追踪（S1）**：沿录制轨迹取“前方约 6–10 码处”的点作为瞄准点（纯追踪），提前转弯、贴轨迹行走。
3. **偏离回拉（S1）**：按偏离轨迹的横向距离加一项修正，偏得越远回得越多。
4. **转速与延迟校准（S3）**：开始移动前小幅试转，实测每毫秒转角与按键延迟；按“所需转角 ÷ 实测转速”算按键时长并提前收键。
5. **弯前减速（S2）**：前方弯越急越早短暂松开前进键，避免到拐点急停。

步骤 4、5 视第 1 步的数据决定是否需要。

### 模块归属（第 1 步）

| 文件 | 层 | 内容 |
|---|---|---|
| `automation/steering_stats.py`（新建） | automation | 横向偏离计算、按段累计与汇总文字（纯逻辑） |
| `automation/navigation.py` | automation | `MapNavigator` 增加只读计数（原地转向、转向点按、受阻），不改控制逻辑 |
| `app/dev_window.py` | app | 回放录制路线时每帧把定位与当前段轨迹交给统计器，到点时写日志 |

### 客户端界面

无新控件；只增加运行日志行。

### 开关与回退

只读统计，不改变移动；无开关。

### 风险

- 每帧多一次点到折线距离计算（轨迹最多 256 点，每段更少），开销可忽略。

## 4. 实现记录

第 1 步：

- `automation/steering_stats.py`：`cross_track_yards`（点到折线的最近距离，按地图码数）；`SteeringStats` 按段累计用时、最大/平均偏离、原地转向、转向修正、受阻次数，结束一段时返回“转向统计 · 第 k/n 段：…”，最后一段附“整圈”汇总。
- `automation/navigation.py`：`MapNavigator.counters`（`stop_turns`、`steer_pulses`、`stalls`），只在原有发键成功与判定受阻处计数，不参与控制判断。
- `app/dev_window.py`：`_observe_steering` 在每次导航观察后调用；仅在当前循环路线为录制路线、且行程的目标是当前停留点时统计；段的轨迹为“上一停留点 + 本段轨迹”；到达停留点（行程完成）写日志；若未到达就切换到其他段，先结算上一段再开始新段。
- 偏离设计之处：无。
